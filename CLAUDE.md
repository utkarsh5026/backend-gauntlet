# CLAUDE.md — backend-gauntlet

A progression of backend/infrastructure projects in Python, easy → hard, built to
learn scale + backend fundamentals by building the primitives from scratch. See
`README.md` for the full roadmap.

## ⚠️ This is a LEARNING repo — default behavior

**The owner writes the interesting code themselves.** Projects are scaffolded with
`raise NotImplementedError` markers and a `SPEC.md` "ticket". Do **NOT** implement
those bodies or solve the SPEC challenges unless the user *explicitly* asks
("implement V1", "write the cache for me"). By default, prefer in this order:

1. **Explain / teach** the concept and tradeoffs.
2. **Hint** — graduated nudges, not full solutions (see `/hint`).
3. **Review** what the user wrote against the SPEC (see `/spec-review`).
4. **Scaffold** new structure (signatures, TODOs, SPECs) — never the meat.

Only write complete solution code when asked outright. When you do, explain it.

**The one sanctioned exception:** during a `/quest`, Claude writes **black-box
acceptance tests** (`tests/test_<module>_acceptance.py`) derived from a vertical's
"Done when ALL true" criteria — *before* the user implements, so they can't encode
the solution. Tests drive the public surface only; implementation stays the user's.

## The "two-axis" SPEC convention

Every project's `SPEC.md` grades on two axes — keep this when scaffolding new ones:
- **Vertical (V1, V2, …):** the scale primitive's internals, built from scratch
  (the parts you'd normally `uv add`). Each has a "concept to internalize".
- **Horizontal checklist:** protocols, caching, security, observability — woven in.
  Every project also carries a **Python & runtime** section: pyright strict clean,
  no blocking call on the event loop, bounded pools sized on purpose, graceful
  shutdown, and a committed profile.
- A **Definition of done** that requires a `bench/` with real numbers + a design doc,
  and a `py-spy` flamegraph + `memray` run naming the top bottleneck.
- The bench requirement is staged as a **🐉 Boss fight**: a named, themed load/failure
  scenario (e.g. "The Thundering Herd") right after the Definition of done, with a
  short flavor paragraph, an **Arena** line (how the fight runs), a **"The boss falls
  when ALL true"** `- [ ]` block of explicit numeric targets (RPS, p99, hit ratio —
  observable outcomes, still no solution steps), and a **Proof** line pointing at the
  benchmark doc. One boss per project (reference: `projects/01-url-shortener/SPEC.md`).
  `tools/status.py` counts the boss's boxes in the horizontal checklist — that's intended.
  **Boss numbers are not scaled down for CPython:** where a target is out of reach,
  the gap and its cause (GIL, GC, allocation, a blocking call on the loop) is the
  finding, recorded in that project's `docs/NN-benchmarks.md`.
- SPECs describe *what* and *why*, never the solution. No spoilers.
- Some SPECs end with an optional **`## 🔬 From the field`** section (generated by
  `/harvest` from that project's `RESEARCH.md`): an *ungraded* adoption backlog of
  industry techniques. Its boxes deliberately use `[~]` (open) / `[✔]` (adopted)
  so they are never counted toward progress bars — never "fix" them to `[ ]`/`[x]`.
  Detail view (`make NN`) shows them under **FROM THE FIELD** when present.
- **Acceptance-criteria format** (reference: `projects/01-url-shortener/SPEC.md`):
  every challenge — verticals *and* the Definition of done — carries a **"Done when
  ALL true"** block of `- [ ]` criteria that are **observable outcomes, never
  solution steps**, plus a **"Proof"** line naming the test/bench/doc that
  demonstrates it. A box only flips to ✅ when its Proof exists. The SPEC opens with
  a one-paragraph "How to read this SPEC" note stating this. `tools/status.py` counts the
  per-vertical "Done when" boxes toward that vertical (its `[done/total]` bar) and
  the horizontal checklist separately, so don't double-list a vertical's criteria in
  the horizontal section.
- Each `SPEC.md` opens with a render-invisible status block (used by the tracker):
  ```html
  <!-- status:
  state: active            # active | paused | blocked | done | not-started
  blocked-on: ~            # free text, or ~ for none
  -->
  ```
  Keep each vertical heading as `### Vn. <title>` and name its
  `src/<package_name>/<module>.py` once inside that vertical's section — the tracker
  maps vertical → module from it.

## Layout & conventions

- **uv workspace, uv only** (never pip/poetry). The root `pyproject.toml` is a
  *virtual* workspace root; every project and `packages/common-*` is an **explicit**
  member of `[tool.uv.workspace]` (not a glob), and the single root **`uv.lock` is
  committed**. Add a member when scaffolding a project.
- `packages/common-*` are **fully implemented** shared helpers (telemetry, config,
  aws), reused by every project. These are the exception to "don't write the meat".
  **`common-aws`** owns the Tier 8 wire envelope — `AwsError` + error rendering,
  `X-Amz-Target` dispatch, the batch partial-failure shape, the Query protocol,
  ARNs, signed pagination cursors. It stops at the *envelope* on purpose: no
  SigV4 (that is 25's V1) and no service semantics.
- `projects/NN-name/` — one project each. The package name omits the number
  (`projects/01-url-shortener` → package `url-shortener`, import `url_shortener`).
- **src layout:** `projects/NN-name/src/<package_name>/` with one module per vertical,
  plus `main.py` (wiring complete — config, lifespan, router, graceful shutdown),
  `config.py` (pydantic-settings, one field per `.env.example` var), `errors.py`
  (AppError→HTTP), `routes.py`, `state.py`.
- **`raise NotImplementedError` is the worklist** — not a bug. `tools/status.py`
  counts it per vertical.
- Stack: **FastAPI + uvicorn (uvloop), pydantic v2, httpx, structlog,
  prometheus-client**; tests are **pytest + httpx `ASGITransport`** (not Starlette's
  `TestClient`); **pyright `strict`** and **ruff** must both be clean.
- Telemetry and settings come from `common_telemetry` (`init`,
  `RequestIdMiddleware`, `metrics_routes`) and `common_config.BaseConfig`.
- **The uvloop trap.** Production runs uvloop (`uvicorn[standard]`, `loop="auto"`);
  pytest runs the stdlib loop. uvloop does not implement the `loop.sock_*` family, so
  code using it passes tests and dies in the container. UDP: `create_datagram_endpoint`
  bridged into a **bounded** `asyncio.Queue`. TCP: `asyncio.start_server`. Boot the
  project's `Dockerfile` to prove it.
- `make verify` per project = `fmt-check → lint → types → test`, the same gate CI
  runs. Task runners use `register_python_checks` / `register_python_run` from
  `tools/makefile_runner.py`.
- **Docker host ports are project-scoped:** host port = the service's conventional
  port with the last two digits replaced by the project number `NN` (postgres →
  `54NN`, redis → `63NN`, nats → `42NN`, clickhouse-http → `81NN`, …). Only the
  *host* side of the mapping changes (`"5404:5432"`); container-internal ports stay
  canonical, so healthchecks and service-to-service URLs are untouched. Apply this
  when scaffolding any new project, and keep `.env.example` + code fallback URLs in
  lockstep with the compose file.
- **Frontend / web projects** (a project's `web/` folder — dashboards, playgrounds,
  admin UIs that front a project's backend): use **Bun** (not npm/pnpm) for install,
  run, and scripts. Stack is **React + TypeScript + Tailwind + shadcn/ui**. Pin
  **TypeScript 7** (`typescript@^7`, the native Go compiler — `tsc`'s only bin now);
  no `baseUrl` in tsconfig (removed in TS 7 — use `paths` alone), and include a
  `src/vite-env.d.ts` with `/// <reference types="vite/client" />` so side-effect CSS
  imports type-check (TS 7 errors on undeclared side-effect imports). Default to a
  **dark theme** and a clean, minimal, uncluttered UI — generous spacing, restrained
  color, good typography; favor shadcn primitives over hand-rolled components. Apply
  this whenever scaffolding or building any web frontend in this repo.

## Commands

```bash
make setup                         # one-command dev env bootstrap (python bootstrap.py)
make doctor                        # diagnose the dev env, change nothing (--check)
make status                        # progress dashboard across all projects
make status NN=02                  # drill into one project (verticals + open items)
make trophies                      # 🏆 achievements (auto-derived — never award by hand)
make infra                         # web panel: per-project Docker deps, up/down, port conflicts
make dev NN=01                     # one-window dev stack: deps + server + frontend (multi: NN="01 03")
make docs                          # read every doc in a browser tab (live-reloads; NN=10 opens that SPEC)
make md NN=01                      # read one project's markdown in the terminal (glow)
make hooks                         # once per clone: enable .githooks (ruff before commit/push)
make preflight                     # ruff format --check on the CI-gated paths
make preflight-lint                # ruff format --check + ruff check

uv sync --all-packages             # install every workspace member into the root .venv

# per project (run from projects/NN-*/):
make help                          # grouped task list (backed by makefile.py + tools/makefile_runner.py)
make verify                        # fmt-check → lint → types → test (the CI gate)
make run                           # the project's console script, .env loaded
docker compose up -d               # start its deps (postgres/redis/…)
```

Per-project `make` targets are implemented in `projects/NN-*/makefile.py`, which
imports shared runner infrastructure from `tools/makefile_runner.py` (console
helpers, uv/docker bundles) and `tools/makefile_help.py` (Rich help tables).
The per-project `Makefile` is a thin wrapper that forwards to `makefile.py`.

`make docs` is the one tool that lives **outside** this repo: it was generic
enough to extract, so it is now [tome](https://github.com/utkarsh5026/tome)
(`uv tool install git+https://github.com/utkarsh5026/tome`). The conventions it
used to hard-code — SPEC-first reading order, `projects/*` as sidebar sections,
the ⚔️ tab icon — live in `.tome.json` at the repo root. Change reading behaviour
there, not in a tool file.

`raise NotImplementedError` bodies fail at runtime by design — that's the worklist,
not a bug. A green `make verify` with every vertical still raising is the expected
scaffold state.

## Style

- Match surrounding code; idiomatic async Python (asyncio, FastAPI). Annotate
  everything — pyright strict is the bar, and every `# type: ignore` carries a reason.
- Errors are exceptions: raise `AppError` subclasses and let `errors.py` map them to
  HTTP. Don't thread result objects through call chains.
- SQL is always parameterized, never string-built. Where the SQL *is* the lesson
  (e.g. `SKIP LOCKED`), use asyncpg with raw, parameterized SQL.
- Never log secrets/API keys. Never commit `.env` (it's gitignored).
